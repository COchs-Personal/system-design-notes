# Understand the project

This repository is a collection of study notes based on the System Design Interview books, volumes 1 and 2. The root `Readme.md` attributes that origin and calls the notes a work in progress. It links 28 numbered topic directories, a published notes site and additional reading. It is not an implemented backend, tutorial application or benchmark suite.

Use it as a map of design questions and tradeoffs. A diagram of a chat service is an explanatory model, not a deployment that can be started. A storage estimate in a chapter depends on that chapter's assumptions, not measurements of your own product. The most valuable skill is learning to connect a requirement to a design decision and then identify what evidence would validate it.

The chapters progress from scaling and estimation through common infrastructure and product examples: rate limiting, consistent hashing, key-value stores, IDs, URL shortening, crawling, notifications, feeds, chat, autocomplete, video, drive-style storage, geospatial services, queues, monitoring, aggregation, reservations, email, object storage, leaderboards, payments, wallets and exchanges. They need not be read strictly in order, but the first three establish useful vocabulary and an interview framework.

There is no canonical project memory key supplied for this study repository. It remains independent of other project architectures. Do not turn hypothetical chapter diagrams into claims about a live application or import private project details into notes merely to make examples feel concrete.

Attribution matters. The repository's educational origin and external links should remain visible. A local copy of study notes is not permission to reproduce entire source books or redistribute all third-party images. This handbook summarizes the repository's structure and maintenance contracts rather than reproducing the chapters wholesale.
